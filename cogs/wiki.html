A 2D co-op space game rebuilt in Unity 6 (URP 2D) with Netcode for GameObjects. 2–4 players crew one shared ship, chart a course across a generated star map, and race the Forgers to the Last Gate. This wiki lists the actual mechanics, with their numbers where the repo states them — it never invents a number.

Status key

Every mechanic on this wiki carries one status. The wiki never invents a number: values come from the design docs or the pure rules in Assets/_Project/Scripts/Core (namespace Astra.Core), and each page cites its source file.

  • Implemented Rules and tests exist in Core, and usually a network layer / scene wiring too.
  • Designed Written up in a design doc; no code (or only partial code) yet.
  • Locked A story decision Steven locked. Do not change without Steven.
  • In transition Being removed or renamed; docs and code disagree for now.
  • Conflict Two repo sources disagree. The wiki flags it instead of picking a winner.
  • WIP Work in progress / placeholder. Merged or written, but not finished, not yet given a full wiki page, or standing in with placeholder numbers, icons or art. See Work in progress / placeholders.

Story spine Locked

Source: Astra_Story_Spine.md (locked 2026-11-01), Astra_World_Design.md §1

One sentence: a lovable-idiot misfit crew stole the map to the Last Gate from the robotic Forgers who guarded it, and now the Forgers chase them across the run while the crew races to the Gate, which jumps to secret coordinates holding an El Dorado-type prize.

  • One theft, one pursuer, one destination, one prize. The crew's motive is greedy, selfish treasure-seeking — they are not saving the universe and not trying to get home.
  • The pursuers are the Forgers (renamed from “Wardens” 2026-11-03, Steven): a robotic race that gained sentience — enigmatic hoarders on poor terms with the rest of the galaxy, not a police force. The map was a piece of their Collection. Code identifiers still use the old name (warden, wardenProximity, lastGateWarden…) and are legacy names to be renamed later — the wiki uses “Forgers” and notes the old IDs where they matter.
  • The Last Gate teleports / jumps the crew to secret coordinates. “Last Gate” is just its name — no lore explanation for why it is the last one. What is through the Gate stays ambiguous; the Forgers cannot follow, because the map is the key.
  • No starter encounter at all (Steven, 2026-11-01, later the same day as the lock). The run opens with the getaway cutscene (short intro), then the crew chart a course. The old lastGateTheft encounter is switched off, and the stolen map simply works — a planned “decrypt the map” random encounter was cut 2026-11-04 (“decrypt the map feels weird as a random encounter”).
  • The heist is not gameplay — at most the short intro/getaway cutscene.
  • Run shape: FTL-style run, one main outcome, 2–4 player co-op only, comedic crew vs. weird horror-tinged universe. Dialogue lives in the travel/encounter layer only, never interrupting live combat.

Cut — do not resurrect without Steven

  • Quarantine / contamination framing
  • A second antagonist creature (the Creature as a second chaser)
  • The wormhole as a plot driver
  • A black-hole opening
  • Wendigo as end boss — Conflict the Wendigo still appears as a large ship in Astra_Space_Combat_Design.md (v2); the wiki flags it, it does not resolve it.
  • The nine-boss sequential run (bosses are deferred, not cancelled — Astra_World_Design.md §5.6, D2)

Flavour targets (Steven's words): a little Guardians of the Galaxy, a little FTL, a little Star Trek — plus Indiana Jones / Holy Grail quest energy.

The run & star map Implemented

Source: Assets/_Project/Scripts/Core/StarMap/SectorRun.cs, StarMapGenerator.cs, StarMapState.cs, MapPatrols.cs; Astra_World_Design.md §5

Run shape

  • 5 slots: slot 1 is always the Free Ports; the next three “breaks” each offer 2 core sector types (each type at most once a run; the cult is at half weight); the last slot is always the Last Gate. About 2 runs in 3, one break offers a rare sector in place of a core type.
  • Each sector map: 18 beacons — 6 columns × 3 rows — plus start and exit edge beacons, with forward-only (Slay-the-Spire-style) paths. Every crossing is 7 jumps.
  • Store chance: 12% of stars are stores (MapOptions.StoreChancePercent = 12 in SectorRun.cs). Conflict Astra_Store_Design.md says about 1 in 5 (20%).
  • The Gate is placed at the farthest non-store star on the right of the map (StarMapState.PlaceGate).

The chase — Forger pressure & the fleet Implemented

Source: Assets/_Project/Scripts/Core/GateRules.cs (WardenPressure, WardenFleet — old names, see Story)

Pressure level (0–4)

  • 0 = a rumour, 4 = on top of the crew. Set by the story flag wardenProximity, and it also climbs by itself: one level every 3 jumps (or per JumpsPerLevel inside a sector — see the sector table). Whichever is higher wins.
  • Inside a sector: level = sector pressure floor + slot number (capped at 3 from that alone), +1 per JumpsPerLevel jumps made in the sector, or the story flag if higher.
  • Patrol chance on a jump: 0% at level 0, otherwise 8 + 10 × level % (18% / 28% / 38% / 48% at levels 1–4). Boons/burdens can shift it.
  • From level 2, a Forger encounter can be a checkpoint instead of a patrol (about half the time).

The fleet front (FTL-style)

  • A front sweeps across the star map from the left. It starts 8% of the map width behind the landing star and advances 4.5% of the map width per jump.
  • On a sector map it advances 9.5% per jump — FTL's pace, so heading for the exit stays ahead and a couple of detours for a store are about all the slack there is.
  • Every star behind the front is Forger-held; arriving at one means a Forger patrol.

Getting through the Gate

  • Arriving at the Gate triggers the approach encounter (lastGateApproach). Every arrival brings the Gate's approach closer until the crew get through — getting through wins the run.

The Rival — a second hunter on the map Implemented

Sources: Assets/_Project/Scripts/Core/StarMap/RivalHunt.cs, MapPatrols.cs (changed in the same merge), commit 1a345c25 (“The Rival hunts the Astra on the star map; the sector exit is the Jump Gate”, StevenGin, 2026-11-05, merged to main as e8824e89)

The Forgers chase from behind (the fleet front and their random patrols). The Rival is a different kind of hunter: one ship on each sector's map, shown there, that hunts the Astra — a treasure-hunter crew who want the stolen map. No proper name: it is “the Rival”, the same treasure hunter as the Buyer (see Astra_Recurring_Characters.md).

  • Placement: when a new sector starts, the Rival turns up on its map on a star away from the Astra — as far as it can, up to 3 hops away (StartHopsFromShip = 3), never on the start star, the Jump Gate, or a store. Not at all once it is finished (see below).
  • Movement: every time the Astra jumps, the Rival has a 50% chance (MoveChancePercent = 50) to move one lane closer to the Astra (never onto the start or the Jump Gate). If it ends up where the Astra is, that is a meeting.
  • Meetings — three, in turn: rivalHunt1 (the first meeting), rivalHunt2 (the grudge), rivalHunt3 (the last stand). Every meeting drives it off this sector's map; it is back in the next sector, until the last stand, after which it is gone for the run.
  • Direction (Steven, 2026-11-05): “Better rival system of other ships/crews trying to get a hold of your map, and them coming back later”, and “Replace patrols purely with rival crews”. In transition — that replacement is a direction, not a completed change: the Forger patrol/chance code in GateRules.cs still exists alongside the Rival. See Conflicts.
  • Sector exit: the same merge names the sector exit the Jump Gate (the exit beacon of a sector map).

Ship combat Implemented — two designs, newer wins

Sources: Astra_Space_Combat_Design.md (v2, 2026-10-20, updated 2026-11-03 — current), Astra_Ship_Combat_Design.md (draft 2, 2026-10-15 — superseded where it disagrees), Assets/_Project/Scripts/Core/ShipCombat.cs, Balance.cs, MissileSupply.cs, ActiveShield.cs, Astra_Faction_Combat.md (proposed)

Space combat v2 is the current design: no separate fight screen — the fight happens in the same world space as the ship. The Astra stays still; enemy ships drift about in a patch of space in front of its nose. The gunner aims with the mouse (the gun turns towards the cursor, limited turn speed); whoever sits in the gunner's seat zooms the camera right out to see the whole patch.

What v2 changed (and what it removed)

  • No retreat. (Justin, 2026-11-03) A ship fight is fought to the end. The retreat drive, the pilot's jump-away bar and its fuel cost were removed. Any mention of retreating below is out of date. Conflict the older draft-2 doc and the damage-control doc still describe a retreat jump (charge ~20s at the helm, costs 1 fuel, counts as a failure) — and ShipCombat.cs still models a pilot evasion bonus (see below).
  • The pilot does nothing in combat for now — no evasion bonus in v2. Conflict ShipCombat.cs still has BaseEvasionPercent, a pilot bonus default of +25 (cap 75), and Balance.BaseDodgePercent = 33. The code and the v2 doc disagree here; the wiki reports both.
  • Shield raised to 40, hull 300 (placeholders to tune); enemy weapon damage was tripled to suit. A crew member has 3 hearts next to a 300-hull ship, so the crew feel fragile next to it.
  • The ship gun uses missiles. Each shot uses a missile from the gun's magazine: 3 for the Ship gun, 2 for the Heavy cannon. The magazine is full when a fight starts; an empty gun cannot charge. Practice shots outside a fight stay free.
  • Missiles come only from the Missile Making room: one every 2 seconds, and it holds only one (Balance.MissileMakeSeconds = 2, MissileCapacity = 1). Someone has to carry each one to a gun's loading spot. Two guns share the one maker, so once the starting magazines are spent the whole ship fires at most about one shot every 2 seconds plus the walk.
  • One shot per press: holding the button charges for 3 seconds (Balance.GunChargeSeconds), then fires; a pellet can look like it touches an enemy and still miss.

Weapons are hand-fed: a weapon holds a few shells/missiles, then somebody has to fetch one from the rack/maker, carry it across the room and load it. The Gunnery room has a rack and two mounts (limit of one Gunnery room). The Bridge starts with a helm, one basic gun console and a small ammo crate.

Defence

  • Hull: at 0 the run is lost. Shield: a pool in front of the hull — hits take shield first, then hull. It recharges after a few seconds without being hit (ShipDefence: shield delay default 4 s, configurable regen).
  • Evasion / dodge (code model): a percentage chance an incoming shot misses; pilot at the helm adds +25 (capped at 75). Balance.BaseDodgePercent = 33, halved per engine down, 0 with none working. See the v2 conflict note above.
  • Emergency shield (big enemy ships only): goes up when the ship is hit, blocks every shot for 4 s, then needs 12 s to recharge (ShieldBounce defaults; ActiveShield).

Enemy ships

  • Defined by race and class, from encounter text (spawnShip(race, class, qty)). Each has hull, shield, shield recharge, evasion, and weapons that fire automatically at the Astra whenever charged. Killing every enemy ship wins the ship side.
  • Movement goes by size class (built 2026-11-02): Small = wander 360°, Medium = arc sweep (half-angle 60°), Large = still, ahead only.
  • Capital ship (test ship): 240 hull — needs 40 hits at 6 damage. Volley Fire: three weapons (4, 4 and 8 damage on 4, 4 and 7 s charges) fire together as a 16-damage volley every 7 s. The Raider (30 hull) needs 5 hits — about what the starting magazines hold.
  • Per-faction styles (Astra_Faction_Combat.md — much of it proposed/config-only, not implemented): Forgers relentless fortress, Pirates fast/fragile boarding thieves, Death cult ritual carrier, Trade guilds defensive convoy, Dryad regenerative bloomship, Avian fast/precise, Rival hit-and-run scout.

Boarders

Enemy ships can send boarders: shuttles fly in (Balance: speed 5, attach 5 s, capacity 4, stagger 3 s), boarders walk at 70% of player speed and attack every 2.5 s. See Ground combat for their damage. Boarders can breach doors (Combat.cs: breach rate, break-down vs other breach kinds).

Ground / onboard combat Implemented

Sources: Assets/_Project/Scripts/Core/Combat.cs, Health.cs, Balance.cs, Oxygen.cs, Boarding.cs, Astra_Space_Combat_Design.md §Boarders

Crew health

  • Each crew member has 3 hearts. Hearts have hit points; damage is tracked in quarter-hearts (CrewMemberHealth). Down at 0; revive restores a fraction of max (ReviveWeak revives crew below 20% to 20%).
  • Boarder attacks (every 2.5 s): glancing blow — quarter heart, 50%; regular hit — half a heart, 35%; critical — a whole heart, 15%. Average 0.45 hearts per attack, so one boarder takes about 17 seconds to kill someone standing still. A critical is announced in the feed.
  • Movement: player speed 2.8 tiles/s; enemies at 70% of that. Dash: start speed ×5, slows at rate 9, ends ×0.67 — about 1.35 tiles in ~0.22 s, cooldown 2 s.
  • Personal gun: handgun damage 66 per module point (~100 hits to knock out a 50-health module); bullet speed ×0.5, fire rate ×0.5, minimum bullet speed 4. Cannot shoot while carrying a shell or a repair kit.
  • Medical Bay: heals a quarter-heart every 6 s (Balance.MedicalBayQuarterSeconds = 6).

Oxygen, fire & leaks

  • Oxygen: drains 0.5/s per person in a room, refills at 2.5/s, equalises through open doors at 0.04/s. Low oxygen at 25; suffocation costs a quarter-heart every 4 s. Rooms show an air gauge (bigger/coloured below 60%, red at 25% and below) with the cause: LEAK, FIRE, O2 OFF, OPEN DOOR, CROWDED. Below 25% the screen edges pulse red with “NO AIR — GET OUT” and an arrow to the nearest room with at least half its air.
  • Fire: 25% chance on a damaging hit; spreads every 7 s with 60% chance (5 s cooldown between spreads); burns hull at 0.25/s and air at 0.5/s; goes out when air is at 15 or below. Putting a fire out takes 2.5 s; a fire burns a quarter-heart every 2 s.
  • Leaks: 25% chance on a damaging hit; leak drains air at 1.5/s. Breached rooms show air wisps swirling into the crack.
  • Weapon hazard: 40% chance (Balance.WeaponHazardChancePercent) — context in Balance.cs / ship systems.

Conflict The doc says room health is 0–100, but DamageControl.cs has RoomPerformance.MaxHealth = 50 with FineAbove = 75 and DamagedAbove = 40. The thresholds and the max do not line up on a 0–100 scale — check whether the code thresholds are percentages or the doc scale is stale. The doc also says room damage = the hit's hull damage × 4; the code has DamagePerHullPoint = 1. Same check needed.

  • A hit that gets through the shield damages the hull and the room it lands in. Damage stays between encounters until repaired. The ship tab shows each room's stage; the feed says what it costs (“Gunnery is damaged: guns charge slower”).
  • Which room is hit: each enemy weapon has an Aim (Random, Guns, Power, Bridge, Medical, Lab). A hit goes to the aimed kind of room 60% of the time if the ship has one, otherwise to a random built room. Examples (starting point, author to confirm): pirate popguns Random, avian feather cannons Bridge, dryad spore launchers Power, imperial lances Guns, cyber lasers Lab.

Repair — carry a kit

  • Repair locker: holds repair kits. One in the Bridge to start; more could be added later. Taking a kit costs 1 Scrap from the crew's shared pool.
  • Carrying: one kit at a time, like a shell — slower (×0.7), personal gun off, kit dropped if the crew member goes down. Cannot carry a shell and a kit at once.
  • Using it: stand at the damaged room's repair point (spanner icon) and hold E for about 1.5 seconds. One kit restores 30 health (about one stage) and is used up.
  • Passive repair: DamageControl.cs has PassiveRepairAmount = 10 — a small free repair per room after every encounter, so a ship that never gets a kit does not slowly die. (The doc listed this as a recommended open choice; the constant exists in code.)
  • Fires, sparks and crew damage from rooms: not yet — rooms only. Boarders do not damage rooms (for now — only enemy ship weapons do).

Ship systems & rooms Implemented

Research (Lab)

Source: Assets/_Project/Scripts/Core/Research.cs

  • Research specs have an id, name, description, coin cost, and a number of steps; some have prerequisites. One active project at a time; steps advance per encounter.
  • Effects: unlock a room, unlock a weapon, ship stat bonus, or crew stat bonus. A damaged Lab still researches normally; a Critical Lab advances only every other encounter; an Offline Lab pauses research.

Economy & stores In transition

Sources: Astra_Store_Design.md, Assets/_Project/Scripts/Core/Store.cs, Astra_Fuel_Removal.md, Astra_Production_Removal.md (both 2026-11-02)

Resources — what Last Gate encounters use now

Coins, Food and Scrap only. Fuel and Production were cut from the Last Gate encounter sheets on 2026-11-02 (Steven's direction), with a strict rule: fuel costs became scrap costs of the same size (scrap is now the engine-strain currency), fuel rewards became production and then, when production was cut the same day, production rewards became scrap (or, for the Forge trades, coins / a looser chase). After both cuts, no Last Gate choice row contains “fuel” or “production”.

In transition — the cuts cover the Last Gate encounter sheets only. Fuel and Production are not yet out of the game: starting resources were Coins 60, Food 20, Scrap 20, Fuel 15, Production 10 (Nov 1 code read, quoted in the removal docs), and removing them from the resource type, UI, starting setup and the original (non–Last Gate) encounters is Justin's follow-up, not yet confirmed. Do not tell players fuel/production are gone until that lands. Scrap now carries both cuts' load and is the most-taxed resource — the docs flag this as a balance watch, not a lock.

Stores

Status (doc): built — rules, tests, network layer, Store page, map markers; play-tested solo by script, not on two machines.

  • A store star is marked with a gold mark and [STORE] from the start so the crew can plan. Jumping to a store star draws no encounter. The store is open while docked, no encounter or fight running, and the run still going. Leaving closes it.
  • Shop from the STORE page on the ship menu (I). Any crew member can buy and sell; the server checks every deal. Store chance is 12% per star in code (see The run — the doc says ~20%).
  • Prices (defaults in StorePrices, editable in the config asset; buy / sell per unit): Food 4 / 1, Scrap 5 / 2, Fuel 10 / 4, Production 8 / 3 — Coins cannot be bought or sold. (Fuel/Production rows are still in the code prices; see the transition note above.)
  • Hull repair: up to 50 hull for 10 Coins (a part pack costs in proportion). Room repair: 5 Coins per damaged room, brings every room to full health.
  • Weapons: 3 on the shelf per store, rolled the first time you dock and kept (a bought weapon stays sold). Price = coin value (10 if none) × level multiplier (1, 2, 3, 5, 8, 12). The store pays 50% when you sell. You cannot sell a weapon someone is holding.
  • Not stranded at a store: running out of fuel normally ends the run (Adrift). While docked at a store you are not adrift if your Coins, plus what the store would pay for your other resources and spare weapons, cover the fuel for one jump. (Fuel wording is pre-cut; the rule needs re-checking once fuel is out of the code.)
  • Not built yet: per-star stock or price variation; store art; buying crew healing or repair kits (kits already cost 1 Scrap at the locker); selling hull/room upgrades.

Coins from combat

Defeated boarders drop coins (Combat.cs CoinDrops: enemy templates roll a coin range, defaults 1–3). Ship-fight spoils are on the Spoils page.

Encounters & dialogue Implemented (spec is a draft)

Sources: Assets/_Project/Content/Encounters/Encounter.csv + Encounter_Choice.csv (the data), Assets/_Project/Scripts/Core/Encounters/* (the loader, decks, flow, votes), Assets/_Project/Content/Dialogue/*.ink (Ink scenes), Astra_Dialogue_System_Spec.md v3 (2026-10-26; status: DRAFT SPEC — code built to v3 on 2026-10-28), Astra_Encounter_Outlines_Toward_Last_Gate.md, Astra_Last_Gate_Encounters_Build.md, Astra_Encounter_Quality_Standard.md, Astra_Encounter_Outcomes_Review.md

How encounters work

  • Encounters are data, not code: rows in Encounter.csv (tab-separated, despite the .csv name), with their choices in Encounter_Choice.csv. The loader (EncounterTsvLoader) only loads rows whose first column is TRUE — that flag is the encounter's on/off switch. A test (RealEncounterDataTests) loads these files and fails on data errors, so mistakes here are caught.
  • Only the Last Gate story's encounters are in the files. The 91 encounters ported from the original Astra (ambushes, the Wendigo, distress calls, the tournament and the rest, with 259 choices) were removed after the 2026-11-02 playtest; they are still in git history and the original repo if any is wanted back.
  • Choices spend or grant resources, set story flags (e.g. wardenProximity 0–4), spawn enemies/ships, or chain to other encounters. Outcome verbs are split into applied (the game does them now) vs deferred (“parse but do nothing”) — see Astra_Encounter_Outcomes_Review.md for the per-verb list. Positive shiphp (hull repair from a choice) is untested and deliberately not used in the fuel/production migrations.
  • Encounters are voted on by the crew (see Dialogue below). The run flow, vote sessions and encounter decks live in Core/Encounters (EncounterFlow.cs, VoteSession.cs, EncounterDecks.cs, OutcomeActions.cs).
  • Decks: there is one draw pile in the data, the standard deck — every ready encounter that names a deck names that one. Twelve ready encounters name no deck: they are never drawn at random, they only happen when something chains to them — the Gate approach and finale (lastGateApproach, lastGateFinal), the Buyer (lastGateBuyer), the “Returns” follow-ups, and the three Rival meetings (rivalHunt1–3).
  • Off, but still in the file: lastGateTheft (the theft opener) is switched off — there is no starter encounter, the run opens with the getaway cutscene. lastGateDecrypt is also off in the current data, even though the Gate approach logic still references it. The other not-ready rows are encounters written but not switched on yet. They are listed at the bottom of this page.

Dialogue (Ink)

  • Content: .ink files under Assets/_Project/Content/Dialogue/, one knot per scene (ink Unity integration 2.0.0). Two scene kinds in one system: talking scenes and FTL-style encounters. The Astra.ink story ships with Encounters.ink (six example encounters, two ambient aftermaths).
  • Example encounters in Encounters.ink — test content, not canon (the file says so itself: “FORMAT TEST CONTENT ONLY: not canon”). They are the dialogue system's worked examples, shaped after the ported encounters: derelict (a dark ship — strip it, board it, or leave it; chains to the derelict_aftermath banter), pirate_toll (pay 15 coins, refuse and fight, or bluff), distress_call (answer it, send supplies, or keep flying; chains to the rescued_pilot talking scene), trader (buy/sell scrap, haggle), asteroid_field (thread it, go around, or fly it by feel), and the_caller (the ship's extended warranty — chains to the_caller_again, which is not in any deck at the start). These six are not in Encounter.csv and are not drawn by the encounter decks; they exist to exercise the Ink system.
  • Session: the crew votes on every choice unless a choice is written as one character's moment (no rotating lead). Speakers resolve against the crew; interjections appear as sliding portraits; choices can be gated; there are timers / disconnect handling and a spotlight-fairness rule so no one character hogs the scene.
  • Game hooks: Ink EXTERNAL functions call into the game (IDialogueScript). Tags cover images (#image), countdowns with #default and #timeout, and BG3-style backgrounds as traits.
  • Built to v3 (2026-10-28): DialogueSession, VoiceTracker (replacing LeadTracker), tag parser with BG3 backgrounds, InkDialogueScript, ambient scenes, encounter pages, dialogue pictures (collected by Astra > Dialogue > Collect Dialogue Pictures), and a content test that checks every tag and walks every background.
  • Scope rule: the spec invents no story content, character names or identities — the four ported characters (idol, edgy, chonky, cop) appear only as placeholder premade ids. Dialogue is travel/encounter layer only, never interrupting live combat.

Boons & burdens (Oddities) Implemented

Source: Assets/_Project/Scripts/Core/Boons.cs (BoonDef, BoonCatalogue, RunBoons)

Run-long modifiers, good (boons) and bad (burdens), held for the run. Each has an id, name, text and a burden flag. Effects the catalogue can apply include: max hull, crew hearts, skill bonus, patrol chance, Warden/Forger level, hull / coins / scrap per jump, fire spread, repair speed, move speed, dash recharge, shield up-time and recharge, missile capacity, dodge, air drain, healing, scrap per fire put out, damage taken and damage dealt. They feed the chase (patrol chance, Forger level), the economy (per-jump resources) and combat (dodge, shield, damage) — see RunBoons for the exact sums.

Oddities are also a spoils choice after a won ship fight — see Spoils.

Spoils — after a won ship fight Implemented

After a won ship fight the crew vote on one of three spoils:

  1. An Oddity not held yet (a boon/burden from the catalogue).
  2. A gun a level better than a kill drop.
  3. Supplies: 60 hull or 15 scrap.

Built as an encounter in code, so it uses the usual vote panel. Debug panel: “Win ship fight”.
